## 0. 三十秒速查

**改前端（`*.html` / `assets/*.js` / `assets/style.css`）**

```bash
cd /e/workbuddy2/fzjh-rank
node --check assets/app.js                    # 1 语法（改哪个查哪个）
python scripts/stamp_assets.py                # 2 【必做】刷 ?v= 缓存戳

# 4 curl 确认 + 浏览器硬刷 + App 内 WebView 各看一眼
```

漏掉第 2 步是本项目最常见的事故：**代码上线了，但 App 内 WebView 还在跑缓存里的旧脚本，页面毫无变化**。

**改数据**（`data/**`）→ 一般由定时任务自动提交；要立即生效就手动触发 workflow（§5.2），或本地跑生成脚本再推（§5.4）。

**改后端 / API**（`api/`、`cloud/`、`worker/`）→ 重新生成部署包并部署（§6），静态站本身不受影响。

## 3. 先判断改动属于哪一类

| 改动 | 通道 | 用户感知 |
|---|---|---|
| `*.html`、`assets/*.js`、`assets/style.css` | **A 前端**（§4）：改 → `node --check` → **`stamp_assets.py`** → 推 main | 刷新页面（App 内要等缓存戳生效） |
| `data/**` | **B 数据**（§5）：定时任务 / workflow_dispatch / 本地脚本重生成 | 下次打开页面 |

## 4. 通道 A：前端代码改动

### 4.1 改代码

- 新筛选 / 排序 / 展示逻辑改 `assets/app.js` 或 `exp.js`；DOM 容器加在对应 HTML；样式加在 `style.css`。
- 只用现有 CSS 变量（§7.2），别写死颜色。
- 新增交互控件时同时考虑桌面表头与窄屏 `.sortbar`（§7.1）。

### 4.2 语法检查

```bash
node --check assets/app.js
node --check assets/exp.js
node --check assets/lookup.js
python -m py_compile scripts/*.py          # 若同时改了脚本
```

### 4.3 【必做】刷缓存戳

```bash
python scripts/stamp_assets.py
```

脚本扫 `index.html` / `exp.html` / `lookup.html` 里 `./assets/xxx.(css|js)?v=` 引用，把 `?v=` 换成文件内容的 md5 前 8 位；内容没变则不改文件，可重复执行（`lookup.html` 目前没有 assets 引用，通常显示「无需改动」）。输出示例：

```
index.html   更新  style.css=34089802 app.js=d7802752 ...
exp.html     更新  style.css=34089802 exp.js=4186931e
lookup.html  无需改动
完成：2 个页面被更新
```

- **改了 JS/CSS 就必须跑**，并把改过的 HTML 一起推（戳写在 HTML 里）。
- **不要手改 `?v=`**，也不要用递增数字；哈希由脚本算。
- 只改 HTML 结构、没动 assets 时不用跑，但 Pages 本身仍有 30–90 秒缓存。

> 历史事故：给高手榜加「转数筛选」和「移动端排序」时，`app.js` 推上线了但没刷 `?v=`，App 内 WebView 继续跑缓存里的旧脚本，页面上完全看不到新功能；桌面浏览器硬刷能看到，两者不一致，排查了很久才定位。

### 4.4 本地预览

```bash
python scripts/serve.py 8791               # 默认 8791，静态站
# 浏览器打开 http://127.0.0.1:8791/index.html?s=taptap_4
```

`serve.py` 修了 Windows 上 `http.server` 调 `socket.getfqdn()` 遇到非 UTF-8 主机名会崩的问题，别直接用 `python -m http.server`。

带实时查询接口的联调见 §6.5。

### 4.5 发布

**常用：GitHub API 建 commit**（本地 git 与远端常分叉，API 方式不碰工作区）。模板与《APK 修改操作手册》§9.1 完全一致，只把 `files` 换成网页文件，例如：

```python
files = ['index.html', 'exp.html', 'lookup.html',
         'assets/app.js', 'assets/exp.js', 'assets/style.css']   # 按实际改动
```

顺序：`git/blobs` → `git/trees`（带 `base_tree`）→ `git/commits` → `PATCH /git/refs/heads/main`。
用 `base_tree` 很重要：CI 会往 `data/` 提交数据，全量 tree 会把它覆盖掉。

**备选：本地 git 直推**（仅当本地与远端一致）

```bash
git add index.html exp.html lookup.html assets/ scripts/ docs/
git commit -m "网页：xxx"
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u all_proxy \
  timeout 90 git -c http.proxy= -c http.sslBackend=openssl push origin HEAD:main
```

### 4.6 确认线上

```bash
# 1) HTML 里戳是否更新
curl -s --noproxy '*' --max-time 15 https://fzpaihang.github.io/lanlandeku/index.html \
  | grep -o 'assets/app.js?v=[0-9a-f]*'

# 2) 新 JS 是否可取
curl -s --noproxy '*' --max-time 15 \
  https://fzpaihang.github.io/lanlandeku/assets/app.js | grep -c "buildZhuanChips"

# 3) Pages 有延迟，必要时轮询 3–5 次，每次间隔 12 秒
```

再分别用**桌面浏览器硬刷**和 **App 内 WebView** 各看一次。App 内的入口在查询页底部「高手榜」，坐标随版本变化，用 `adb shell input tap` 点开（见 APK 手册 §6）。

## 5. 通道 B：数据改动

### 5.1 定时任务表（`.github/workflows/refresh.yml`）

cron 是 **UTC**，注释里写的是北京时间：

| cron (UTC) | 北京时间 | 分区 |
|---|---|---|
| `0 22 * * *` | 次日 06:00 | `taptap` 苍松迎客 |
| `55 15 * * *` | 当日 23:55 | `taptap_2` 白鹤亮翅 + `taptap_3` 丹凤朝阳 |
| `0 4 * * *` | 当日 12:00 | `taptap_4` 墨羽惊鸿 |
| `0 10 * * *` | 当日 18:00 | `4399` |

- 单区全量 5–8 分钟，五区一次 29 分钟，`timeout-minutes: 45`
- `concurrency: group: fzjh-data, cancel-in-progress: false` —— 串行，不取消进行中的任务
- 定时任务没有 inputs，靠 `github.event.schedule` 反查该抓哪个区；不匹配时 `t='all'`（会把五区全跑一遍，改 cron 时务必同步改 `case`）
- 步骤顺序：连通性探测 → 抓榜单 → 抓档案 → 合并经验 → 重建昵称索引 → 提交 `data/`
- 提交前 `git fetch origin main && git rebase FETCH_HEAD`，最多重试 3 次，避免 non-fast-forward 丢整批数据

### 5.2 手动触发

```bash
# GitHub 网页：Actions → 刷新高手榜 → Run workflow
#   mode:   probe（只探连通性，不写文件） / board（只抓榜单） / full（榜单+档案）
#   server: all / taptap / taptap_2 / taptap_3 / taptap_4 / 4399
gh workflow run refresh.yml --repo fzpaihang/lanlandeku -f mode=full -f server=taptap_4
gh run list --repo fzpaihang/lanlandeku --limit 3
```

`merge-exp.yml` 是**只做合并、不请求接口**的手动流程：把已有 `profiles/` 的经验写回榜单并重写当天快照，适合两次抓取之间修正展示，或切换口径后修历史。

### 5.3 本地重生成（改了脚本 / 要立刻修数据时）

```bash
python scripts/fetch.py --server taptap_4              # 抓榜单（需要 config.json 或环境变量）
python scripts/fetch_profiles.py --server taptap_4      # 抓档案
python scripts/merge_exp.py --server taptap_4           # 合并经验 + 追加快照
python scripts/build_lookup_index.py                    # 重建昵称索引（全分区）
python scripts/summary.py                               # Actions 用的 Markdown 摘要
```

改完 `hidden.json` 必须重跑 `build_lookup_index.py`，否则隐私名单不会进索引的 `hidden` 字段。

### 5.4 经验快照口径（最容易出错的一块）

**背景**：`get_board`（排行榜）对不活跃玩家长期返回旧值，`get_user_info`（档案）更新更勤。`merge_exp.py` 把榜单 `exp` 改成档案整数值、原值存 `expBoard`，**名次 `rank` 保留游戏原始值，不按经验重排**。

**历史坑（v39）**：11-11 那批快照的 `exp` 是直接从排行榜取的浮点值，之后是档案整数值。两套口径相减 → 出现「+21.7 万 / −3.2 万」这类一眼假的增长。

**当前规则（改这块前必须遵守）**：

1. `exp-history.json` 里只保留 `src == "profile"` 的快照；11-11 那批已清掉。
2. `assets/exp.js` 的**当前值和基准都取快照**（`latest.exp[uid]` / `baseSnap.exp[uid]`），快照里没有才退回榜单行 —— 不能一边取榜单、一边取快照。
3. `baseSnap` 取窗口内最早一条，`latest` 取最近一条；只有 1 条时页面显示「暂无对比数据」，日均要区间满 3 天才显示。
4. `merge_exp.py` 同一天重跑会**覆盖当天最后一条快照**（同 `ts` 差 ≤ `SNAP_GAP` 或同 `date`），所以一天只会有一条，不会人为造出第二条。
5. **不要**用 `profiles/` 目录重写基准：那批档案实测是 11-11 21:44 的，比榜单（11-13）还旧，拿它当基准等于倒着比。曾写过 `reset_exp_baseline.py`，已删除，别再恢复。

排查命令：

```bash
python - << 'EOF'
import json, io, glob
for p in sorted(glob.glob('data/servers/*/exp-history.json')):
    d=json.load(io.open(p,encoding='utf-8')); s=d['snapshots']
    print(p.split('/')[-2], len(s), [(x['date'], x.get('src'), len(x['exp'])) for x in s[-3:]])
EOF
```

### 5.5 隐私与昵称

- `hidden.json` 里的 UID 在**生成榜单时已剔除**，索引生成时再过滤一次。
- `extra-names.json` 由 APK / `query_issue.py` 回写，`build_lookup_index.py` 会合并进去。
- 改这三个文件后都要重跑 `build_lookup_index.py` 并推 `lookup-index.json`。

## 6. 通道 C：后端 / API / 云函数

### 6.1 静态查询接口

- `api/query.py` 是 Vercel Python 函数入口；`vercel.json` 指定 region `hkg1`、`maxDuration: 30`、`includeFiles: "**"`。
- 协议核心（`fetch.py` / `lookup_core.py` / `aes_pure.py` / `names.json`）**只有 `apk/` 一份源**，不要复制改。

### 6.2 云函数部署包

```bash
python scripts/build_api_zip.py                # 产出 api/build/fzjh-lookup-api.zip
python scripts/build_api_zip.py --stage-only   # 只准备 api/build/staging，供本地联调
```

包里 = `cloud/fc_index.py`（入口）+ 从 `apk/` 复制的协议核心 + 各分区榜单。入口源文件放 `cloud/` 而不是 `api/`，是为了避免 Vercel 把同名文件误当 handler。

### 6.3 Issue 驱动的查询（`.github/workflows/query.yml`）

网页把 UID 拼成 Issue 标题提交：

```
[QUERY] 7257325
[QUERY] 7257325 @taptap
```

CI `issues.opened` 触发 → `scripts/query_issue.py` 调游戏接口 → 回帖 → 关闭 Issue → 成功时把 uid→昵称归档进 `data/extra-names.json`。

⚠️ 一个 uuid 只保留一个有效会话密钥，**两个查询并发会互相作废旧密钥**，表现为 `errcode 20616`。所以 `concurrency: group: fzjh-query, cancel-in-progress: false` 是全局串行，不能按 Issue 号分组。

### 6.4 Worker 脚本

`worker/build-data.mjs`、`worker/make-dev-vars.mjs` 是 Node 侧的数据/开发变量构建脚本，本次会话未改动；改之前先看脚本头部说明。

## 7. 前端功能区维护指引

### 7.1 加筛选 / 排序的具体位置

| 想加什么 | 改哪里 |
|---|---|
| 新筛选维度（类似门派、转数） | HTML 加 `.chips` 容器（带 `id`）；`app.js` 的 `state` 加字段、`matches()` 加判断、写 `buildXxxChips()` 并在 `boot()` 和 `onMQ` 里调用 |
| 筛选条按条件显示 | 参考 `buildZhuanChips()`：统计去重值，`length <= 1` 时 `el.hidden = true` 并清空内容 |
| 移动端排序 | HTML 加 `.sortbar`（`data-sort` 按钮）；`app.js` / `exp.js` 写 `syncSortButtons()` + `bindSortbar()`，`render()` 里同步选中态，初始化时 `bindSortbar()` |
| 桌面排序 | 表头 `th[data-key]` + `syncSortState()`，`.sortbar` 在桌面由 CSS 隐藏 |
| 卡片/表格列 | `renderCards()` 与 `render()` 两处都要改（窄屏走 cards，宽屏走 table） |

高手榜默认 `sortKey='rank' / asc`；经验页默认 `sortKey='grow' / desc`。切换排序键时，名次类用 `asc`，数值类用 `desc`。

### 7.2 CSS 变量与响应式

`:root` 里的变量（`assets/style.css` 开头）：

```
--bg #f6f4ef   --card #fff   --ink #1f2328   --muted #8a919c
--line #e7e3da  --accent #8c2f28  --accent-soft #f3e7e4
--gold #b8860b  --silver #8a8f98  --bronze #a46a3f
--up #b23a2f（红=涨）  --down #2f7a5c（绿=跌）
--radius 12px  --row-h 48px  --card-h 64px
```

- 断点：`900px` / `720px` / `560px`；`.sortbar` 只在 `max-width:560px` 显示，桌面用表头。
- 涨红跌绿符合国内习惯，别反过来。
- **网页的 `--muted` 是 `#8a919c`，APK 的 `C_MUTED` 是 `#6E635A`**，两套配色别混用。

### 7.3 分区

- `data/servers/index.json` 是唯一来源；`FZJH.init(cb)` 读它、设 `FZJH.base = './data/servers/<key>/'`、写 `localStorage.fzjh_server`。
- 站内链接用 `keepParams()` 保留 `s` / `me` / `uid`。
- **分区列表读取失败不能静默回退**：`servers.js` 会设 `FZJH.listError` 并显示横幅，因为显示错区的数据比报错更糟。

### 7.4 数据不足时的兜底

`exp.js` 只有 1 条快照时显示「暂无对比数据」+ 说明，区间增长列是「—」；这是正常状态，不是 bug。日均要区间满 3 天才出现。

## 9. 硬规则与踩过的坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **改了 JS/CSS 没跑 `stamp_assets.py`** | 代码上线但页面没变化（App 内尤甚），桌面硬刷却正常 | 每次改 assets 必跑，并把改过的 HTML 一起推 |
| 手改 `?v=` 或用递增数字 | 缓存不失效 | 用脚本算内容哈希 |
| **经验快照两套口径** | 「+21.7 万 / −3.2 万」假增长 | 只留 `src=profile` 的快照，前后端都取快照值 |
| 拿 `profiles/` 重置基准 | 档案比榜单旧，倒着比 | 已删除 `reset_exp_baseline.py`，别再恢复 |
| 同一天手动重跑 merge_exp 想造第二条快照 | 会被覆盖，一天只有一条 | 等第二天定时任务 |
| 当前值取榜单、基准取快照 | 又一次口径差 | `exp.js` 两边都取 `latest.exp` / `baseSnap.exp` |
| 转数筛选无条件显示 | 单档分区出现一排死按钮 | 去重后 `length<=1` 就 `hidden` |
| 排序入口只放在表头 | 手机端没有表头 → 无法排序 | 加 `.sortbar`，`@media (max-width:560px)` 才显示 |
| 移动端把「名次」换成「经验」 | 用户要的是默认名次 + 可手动切经验 | 默认 `rank/asc`，另给经验/等级按钮 |
| 分区列表加载失败静默回退 | 整页显示成别的区的数据 | 保留 `FZJH.listError` 横幅 |
| 写死颜色 / 混用两端配色 | 主题不一致 | 用 CSS 变量；注意网页 `--muted` ≠ APK `C_MUTED` |
| `git push --force` | 顶掉 Actions 提交的抓取数据 | 永远不要 |
| 全量 tree 覆盖式发布 | 把 CI 刚提交的 `data/` 覆盖掉 | GitHub API 用 `base_tree` 增量建 tree |
| 两个查询并发 | `errcode 20616` 互踢 | `concurrency` 全局串行 |
| 改 cron 忘了同步 `case` | 落到 `*) t='all'`，误跑五区全量 | 两处一起改 |
| 改 `hidden.json` 不重建索引 | 隐私名单不生效 | 重跑 `build_lookup_index.py` |
| 名次按经验重排 | 与游戏内榜单不一致 | `rank` 保留原始值 |

## 10. 常用脚本模板

### 10.1 发布（GitHub API，通用）

```python
import base64, io, json, urllib.request
TOK = io.open('E:/workbuddy2/_agent_tmp/gh_token.txt', encoding='utf-8').read().strip()
REPO, API = 'fzpaihang/lanlandeku', 'https://api.github.com'
def call(m, p, pl=None):
    d = json.dumps(pl).encode() if pl is not None else None
    r = urllib.request.Request(API + p, data=d, method=m)
    r.add_header('Authorization', 'token ' + TOK)
    r.add_header('Accept', 'application/vnd.github+json')
    r.add_header('Content-Type', 'application/json')
    op = urllib.request.build_opener(urllib.request.ProxyHandler({}))
    with op.open(r, timeout=60) as x:
        return json.loads(x.read().decode())

base = call('GET', '/repos/%s/git/ref/heads/main' % REPO)['object']['sha']
ts = call('GET', '/repos/%s/git/commits/%s' % (REPO, base))['tree']['sha']
files = ['index.html', 'exp.html', 'lookup.html', 'assets/app.js', 'assets/style.css']
entries = []
for f in files:
    sha = call('POST', '/repos/%s/git/blobs' % REPO,
               {'content': base64.b64encode(open(f, 'rb').read()).decode(),
                'encoding': 'base64'})['sha']
    entries.append({'path': f, 'mode': '100644', 'type': 'blob', 'sha': sha})
tree = call('POST', '/repos/%s/git/trees' % REPO, {'base_tree': ts, 'tree': entries})
new = call('POST', '/repos/%s/git/commits' % REPO,
           {'message': '网页：xxx', 'tree': tree['sha'], 'parents': [base]})
call('PATCH', '/repos/%s/git/refs/heads/main' % REPO, {'sha': new['sha'], 'force': False})
```

## 11. 故障排查表

| 现象 | 先查什么 |
|---|---|
| 改了代码页面没变 | **HTML 里的 `?v=` 有没有更新**；`stamp_assets.py` 跑没跑；Pages 是否还在缓存期；App 内 WebView 缓存 |
| 桌面正常、App 内不正常 | 几乎一定是缓存戳没刷 |
| 分区数据显示成别的区 | `data/servers/index.json` 是否可读；URL 的 `s=` 参数；`FZJH.listError` 横幅 |
| 经验增量出现天文数字 / 负数 | 快照里是否混进了 `src != profile` 的旧快照；`exp.js` 是否又混用了榜单行 |
| 经验页显示「暂无对比数据」 | 只有 1 条快照，正常；等第二天定时任务 |
| 高手榜没有转数筛选条 | 当前分区是否只有一档转数（切到 `taptap_4` 墨羽惊鸿验证） |
| 手机端找不到排序入口 | `.sortbar` 是否只在 ≤560px 显示；`bindSortbar()` 初始化了吗 |
| APK 里昵称搜不到 | `lookup-index.json` 是否重建；`hidden.json` 是否把人过滤了；`extra-names.json` 合并了吗 |
| 查询报 `errcode 20616` | 有并发查询互踢会话密钥，等 2 分钟重试 |
| CI 数据没提交 | Actions 日志看 rebase / push 是否失败；`concurrency: fzjh-data` 是否排队 |
| 线上 404 | 文件是否在 main 根目录对应路径；Pages 源是 main 根目录 |
| 本地预览打不开 | 用 `scripts/serve.py`，别直接 `python -m http.server`（Windows 主机名会崩） |

## 12. 不要做的事

- 不要改完 assets 不跑 `stamp_assets.py`。
- 不要手改 `?v=` 版本号。
- 不要 `git push --force` 到 main（会顶掉 Actions 提交的数据）。
- 不要用全量 tree 覆盖式发布（会丢 `data/` 的新提交）。
- 不要提交 `config.json` / `gh.json`。
- 不要恢复 `reset_exp_baseline.py`（会用过期的 `profiles/` 写错基准）。
- 不要把 `src != profile` 的旧快照放回 `exp-history.json`。
- 不要让 `exp.js` 的当前值退回榜单行（口径会再次混用）。
- 不要删 `robots.txt`。
- 不要按经验重排 `rank`（名次是游戏原始值）。
- 不要把网页的 CSS 变量和 APK 的颜色常量当成同一套。
- 不要在修小 bug 时夹带数据流水线重构；数据改动先在小分区用 `mode=probe` / 单区 `full` 验证。
