## 1. 这是什么

《放置江湖》的多平台玩家数据站，三块东西同一仓库：

| 部分 | 是什么 | 跑在哪 |
|---|---|---|
| **网页** | `index.html` 高手榜 / `exp.html` 经验变化 | GitHub Pages（main 根目录，30–90 秒缓存） |
| **APK** | 霜霜妙妙屋：查 UID / 昵称看档案 | Kivy 打包，**日常改动走热更，不重装** |
| **数据** | 8 个分区的榜单 / 档案 / 经验快照 | GitHub Actions 每天 7 个时点抓取后自动提交 |

三者共用同一套游戏接口协议（`apk/fetch.py` 是唯一协议源，`scripts/` 侧复用它）。

## 4. 常见任务 → 命令

所有命令都在 `cd /e/workbuddy2/fzjh-rank` 之后执行，Python 用 `D:\Programs\Python\Python38\python.exe`。

| # | 任务 | 步骤 |
|---|---|---|

| 6 | 加一个分区 | `config.json` 加条目 → 私有 gist + CI Secret `FZJH_SERVERS` 同步 → `lookup_core.py` 前缀表 + `app_ui.py` 兜底列表 → 手动跑一次索引 |
| 7 | 改隐私名单 | 改 `data/hidden.json` → **手动跑一次** `重建昵称索引`（否则旧索引仍能搜到） |
| 8 | 任何改动发布前 | `python scripts/preflight.py`（8 项自检，秒级） |

**发布只有一条路**：`scripts/publish.py`（底层 GitHub REST API，自动带 `base_tree`、跳过无变化文件、

**不要 `git add/commit/push`** —— 本地 git 与远端长期分叉，push 也常被网络掐断。

## 5. 十条铁律

1. **不 `git push`**：一律 `scripts/publish.py`。想同步本地用 `git fetch origin main && git reset --hard FETCH_HEAD`。
2. **改 JS/CSS 必须 `stamp_assets.py`**：漏了就是"代码上线了但页面没变"，本项目最常见事故。
3. **改 `apk/*.py` 必须 `pack_update.py`**：版本号自动 +1，**只升不降**；不打包 `preflight` 会 FAIL（逐字节比对）。
4. **武学等级公式有 3 处活代码**：`apk/lookup_core.py`、`scripts/fetch_profiles.py`、`worker/src/profile.js`（未上线）。
   `api/build/staging/` 是构建产物，跑 `build_api_zip.py` 跟随，不要手改。
5. **加分区要同步 5 处**：`config.json`、私有 gist、CI Secret、`lookup_core.py` 前缀表、`app_ui.py` 兜底列表。
   最后再手动跑一次索引重建，否则新服的人按昵称搜不到。
6. **`data/hidden.json` 改完必须重建索引**：索引里的 `hidden` 字段是 APK 拦截查询的依据。
7. **经验快照只认 `src === "profile"`**：排行榜浮点值和档案整数值不能混算，否则出现假增量 / 负增长。
8. **别手动跑 `mode=all`**：8 区串行本来就慢，全量很容易撞限流（`20616`），抓成半截还可能清空索引名单。
9. **产出全部放 `E:\workbuddy2`**：临时脚本、截图放 `E:/workbuddy2/_agent_tmp`；
   Git Bash 的 `/tmp` 实际在 C 盘，不要用。
10. **决策不明确先问，不要自己定**：尤其是架构拆分、要很久的改造、会影响线上表现的取舍。

## 7. 关键路径速查

### 7.1 代码

| 路径 | 作用 |
|---|---|
| `apk/fetch.py` | **游戏接口协议唯一源**（握手、加解密、请求头、重试） |
| `apk/lookup_core.py` | 分区识别、档案解析、缓存、查询预算、榜单兜底取数 |
| `apk/app_ui.py` | 全部界面（2900+ 行，改 UI 只动这里） |
| `apk/names_index.py` | 昵称索引下载 / 缓存 / 搜索 / 手动刷新 |
| `apk/archive_local.py` | 查到新昵称 → 写仓库 `data/extra-names.json` |
| `scripts/fetch.py` `fetch_profiles.py` `merge_exp.py` | CI 数据链路：榜单 → 档案 → 经验快照 |
| `scripts/build_lookup_index.py` | 生成 `data/lookup-index.json`（**纯本地计算，不发请求**） |
| `scripts/preflight.py` `publish.py` `check_drift.py` | 自检 / 发布 / 漂移比对 |
| `assets/app.js` `exp.js` | 网页榜单页 / 经验页（`profile.js` 已随 `lookup.html` 停用） |

### 7.2 CI（`.github/workflows/`）

| 工作流 | 触发 | 干什么 |
|---|---|---|
| `refresh.yml` | 每天 7 个 cron + 手动 | 抓榜单/档案、合并经验、提交 `data/` |
| `lookup-index.yml` | 每周一 04:00 + 手动 + `extra-names.json` 变更 | 重建昵称索引（**不打游戏接口**） |
| `merge-exp.yml` | 手动 | 单独补跑经验合并 |
| `query.yml` | Issue 打开 | 网页 UID 查询（Issue 驱动） |
| `build-apk.yml` | 手动 / `apk/` 变更 | 重打安装包传 Release |

### 7.3 模拟器

```bash
export MSYS_NO_PATHCONV=1
ADB="D:/Program Files/Netease/MuMuPlayer-12.0/shell/adb.exe"
"$ADB" start-server
"$ADB" connect 127.0.0.1:16384     # 实例端口从 vms/*/configs/vm_config.json 读，别硬编码
"$ADB" -s 127.0.0.1:16384 root      # 读 /data/data 必须 root；run-as 对 release 包无效
```

- 两个实例：`16384`（普通区客户端）、`16416`（华为端 `com.xhtt.app.fzjh.huawei`）。
- 读版本：`cat /data/user/0/com.fzjh.fzjhlookup/files/live/version.txt`
- 热更生效判断：**先看 version.txt，再冷启动一次**；常见"版本号变了但界面没变"就是还差一次重启。
