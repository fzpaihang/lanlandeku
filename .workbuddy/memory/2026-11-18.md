# 2026-11-18

## 00:00–03:20 iOS 三个分区全部接入（v69 → v70 → v71）

**起点**：用户给了三套 iOS 凭据，要求「接进网页和 APK」「定时任务分别放 4 点 / 8 点 / 10 点」「对齐 APK 的昵称检索」。

**之前判断错了**：11-17 深夜我曾断言「iOS 数据拿不到」。错在只试了 `platform=ios` + `channel=fzjh` 之类的组合就下结论。
真值是**三件套必须同时给对**：`domain=https://ios.fzjh.xiaohoutiaotiao.com` + header `platform: ios` + `channel` 与分区一一对应
（老马识途 `ios` / 野马分鬃 `fzjh` / 仙人指路 `fzjh3`）。缺任何一个都 `HTTP Error 500`。
**教训**：连续 500 不等于「没权限」，先怀疑参数组合，把矩阵列全再下结论。

**三个区共用同一个 uuid** `ec1d0471437f40ae901ed3af63ce26f7`，只有 `channel` + `account` 不同 —— 是同一个 iOS 客户端的三种分区视图。
`switch_partition/1|2|5` 是 GET、返回 `errcode 0`、`active_partition` 也真的变了，**但榜单数据始终是同一批人**，所以切区无效，必须换凭据。
`api/service_android/get_uuid` 能铸新 uuid，但铸出来的号 `get_board/1` 一律 0 行 —— uuid 只能来自真实客户端。

**每个区改 7 处**（这是本次反复核对出来的清单，写进了 `docs/网页维护操作手册.md` §5.1.0）：
`apk/lookup_core.py` 的 `UID_PREFIX_SERVER` + `order_servers()` 兜底、`config.json`、`apk/app_ui.py::_servers()`、
`scripts/plan_refresh.py` 的 `SCHEDULE_MAP`+`LABELS`、`refresh.yml`、`merge-exp.yml`、`scripts/build_lookup_index.py` 名字表。
**最容易漏的是 `order_servers()`**：10 位和 11 位是两条不同的分支，加 ios2 只动 10 位、加 ios3 只动 11 位。

**gist 必须是 `{"servers": [...]}` 字典**：第一次贴成裸数组，`apk/lookup_core.py` 的 `if not (cfg.get("servers") or []): return False`
静默失败，设备上只表现为「该分区未找到」，没有任何报错。改回字典立刻正常。
